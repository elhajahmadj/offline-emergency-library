- **The phone-pack builder now reports curl's real error on a failed redirect hop.** After #238, when `curl -L` followed an archive.org `302` and the next hop failed to connect, `get()` reported the stale `HTTP 302` and swallowed curl's actual exit, so the logs blamed the redirect instead of the connection. It now keys the message on curl's exit code: a transport failure reads `curl exit N (last HTTP 302): …` while a genuine server status still reads `HTTP <code>`. Thanks @boostedchaos for diagnosing it and testing the one-line fix. _[@elhajahmadj](https://github.com/elhajahmadj) - PR #241._
